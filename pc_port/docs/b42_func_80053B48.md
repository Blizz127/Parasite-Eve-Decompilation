The body proves this true ABI:

```c
int32_t func_80053B48(pe_addr_t record);
```

Only entry `$a0` is read. It is a 32-bit guest record address, read at byte
offset 6 and halfword offset `0xA`. Entry `$a1-$a3` are irrelevant to the
callee. The sole return site returns exactly 0 or 1: unsupported record types
return 1; supported types return 1 only when their category ID is absent and
the current table has no zero slot. A full table still performs the later
category-record update. No pointer or arbitrary dependency result is returned.

Type mapping is exact: types 1-5 and 16 select category 0; types 6 and 17
select category 1; types 7 and 18 select category 2. Every other byte value
selects no category and returns 1 before reading table state.

`53C60/53C68` compute/divide the free-slot displacement; `53C8C` performs the

write. Conditions are sampled at issue and every delay executes exactly once.

ROM-order semantic phases are:

1. Read `record+6` as one unsigned byte and derive category 0-2 or reject.
2. Read count then base, compute the unsigned wrapped table end, and scan
   signed halfwords for `0x200+category`. Re-read count/base to validate the
   found cursor and derive its signed arithmetic halfword index.
3. If absent, repeat the same bounds protocol while scanning signed
   halfwords for zero. On success re-read base and store the category ID as
   exactly one halfword. On failure set status 1 without returning.
4. Derive `0x800A1E64+(category<<5)`. Read fixed `lhu +0xA`, input
   `lhu +0xA`, fixed `lbu +9`, then fixed signed `lh +0x12`; store the wrapped
   sum to fixed `+0xA` as one halfword.
5. Let `threshold=lbu(+9)+signed_lh(+0x12)` and `sum16=sum&0xFFFF`. If
   `threshold<1000`, rewrite only when signed `threshold<sum16`. Otherwise,
   rewrite only when `sum16>=1000`. The rewrite reloads signed `+0x12` then
   unsigned `+9`, writes that sum if below 1000, or 999 otherwise. Negative
   values are not lower-clamped and truncate at the halfword store.
6. Return the exact status 0 or 1.

## Both executable callers and consumed returns

### `func_80053D2C` at `0x80053E1C`

The jump table at `0x8001125C` sends exactly record types 16, 17, and 18 to
this site. The preceding operation is `jr v0` at `0x80053DF0`, delay `nop`.
Before dispatch, `func_8005DB44(arg-1)` returned the selected guest record;
`0x80053DBC` moved it to `$a0`, it was NULL-checked, and its type byte was
read. At call issue `$a0` is that exact record pointer. `$a1` is the corrected
`0x800A8034` alternate-base word left by raw `func_8005DB44`; `$a2/$a3`
retain the entry values from the caller of `func_80053D2C`. The `jal` delay at
`0x80053E20` is `nop`.

After the call, `j 0x80053E4C` executes `addu s1,v0,zero` in its delay slot;
`0x80053E4C` then executes `addu v0,s1,zero`. Thus `0`, `1`, `7`,
`0x7FFFFFFF`, `0x80000000`, and `0xFFFFFFFF` are all forwarded unchanged.
There is no signed conversion, test, inversion, normalization, later branch,
or cast. The caller performs no persistent write before this type path and no
write after it; B42 state is fully committed before `func_80053D2C` returns.
Repeated invocation redoes the lookup and type dispatch, then observes the
current table/category state. The call is conditional on a non-NULL record
and one of those three type bytes; `func_80053D2C` itself is repeatable, not a
one-shot initializer.

The pre-B42 real-disc stop was this call with `arg=1`, record `0x800AB608`,

## State authority, footprint, and dependency boundary

There are no callees, callbacks, BIOS/Psy-Q/SDK calls, indirect calls, or
unresolved boundaries. B42 does not enter `func_8005218C` or any later rung.

The two `$gp` fields are the existing host-authoritative `unsigned int`
objects in `src/pe_globals.c`; their numerical guest aliases are deliberately
not storage. B42 only reads them. Both survive `PE_RamReset` and are cleared
by `PE_Sdk_ResetState` in `platform/pe_libetc.c`. The exhaustive executable
census remains exactly the 57 readers/30 writers for `D_8009D048` and 43
readers/32 writers for `D_8009D050` listed in
`b40_func_8005332C.md`; B42 is a reader of both and is already present in
those lists. No global is migrated or duplicated.

The category array is guest-authoritative retail data, nine 32-byte records
at `0x800A1E64..0x800A1F83`; B42 addresses only the first three. It is seeded
by `func_80052C6C` and cleared/maintained by `func_8005CCA4`; executable
readers/writers of the B42 fields include `func_80053E6C`, `func_8005D2B4`,
`func_8005C25C`, `func_8005C374`, `func_800553A4`, `func_80056C14`,
`func_80057E14`, `func_8005A318`, and `func_800574A8`. B42 reads bytes/halfwords
and writes only field `+0xA`. Guest RAM is cleared by `PE_RamReset`; there is
no host copy. The selected record and current ID table are likewise solely
guest-authoritative. Corrected record lookup reads `0x800A8034/38`; poisoned
`0x800B8034/38` bytes remain inert canaries, not semantic inputs.

Exact data footprints:

- Every call reads one byte at `record+6`. Supported types also read one
  halfword at `record+0xA`. For checked supported records the record base can
  range from `0x80000000` through `0x801FFFF4`; an unsupported call needing
  only byte `+6` may start through `0x801FFFF9`.
- Each table scan reads signed little-endian halfwords at
  `D_8009D048+2*i`, bounded by the exact unsigned wrapped end. If the category
  ID is absent, entries before the first zero can be read twice. Across valid
  checked states these reads can start at `0x80000000` and at most
  `0x801FFFFE`.
- Fixed reads are byte `+9`, unsigned halfword `+0xA`, and signed halfword
  `+0x12` in records based at `0x800A1E64`, `0x800A1E84`, or `0x800A1EA4`.
  The fixed read range is `0x800A1E6D..0x800A1EB7` inclusive.
- Every supported call writes exactly two bytes at fixed `+0xA` (starts
  `0x800A1E6E`, `0x800A1E8E`, or `0x800A1EAE`), possibly twice at the same
  address. A newly installed ID adds exactly one two-byte write at the first
  zero table slot. Thus the fixed direct-write minimum is `0x800A1E6E`,
  maximum byte `0x800A1EAF`; a data-dependent table write may begin anywhere
  from `0x80000000` through `0x801FFFFE` in valid checked state.
- Unsupported types write nothing. Table insertion is guarded by both
  unsigned range checks and a found-zero check. Every native access uses the
  exact-width checked `PE_Load/PE_Store` API; full-RAM canaries and adjacent
  guards prove there is no other byte write.

There is no executable/rodata data read, hardware access, host pointer,
pointer truncation, low-address mirror, clamping, polling, wait, or blocking.
The function is deterministic from guest RAM plus the two authoritative host
fields, not from guest RAM alone, and has no host-time/environment input.
Address zero remains invalid and is never replaced or mirrored.
