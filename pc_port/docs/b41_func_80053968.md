The body proves this true ABI:

```c

```

archive resource ID; the dependency receives the exact wrapped value
`(uint32_t)resource_id - 1`. Entry `$a1-$a3` are irrelevant. The only machine
return site returns exactly zero if either free-slot search fails, otherwise
the exact destination in `0x800C0EAC + 0x20*record_slot`. It never clamps or
normalizes this return and never returns a host pointer.

## Sole executable caller and consumed-return proof

The sole call is `func_80053D2C` at `0x80053DF8`. Its exact dispatch sequence
is `jr v0` at `0x80053DF0`, delay `nop`, `jal func_80053968`, call delay
`addu a0,s0,zero`, `j 0x80053E4C`, delay `sltiu s1,v0,1`. The 18-entry jump
table at `0x8001125C` sends record types 1 through 9 to this site; no other
type reaches it.

At call issue `$a0` becomes the original signed 32-bit `func_80053D2C`
argument held in `s0`. `$a1` still contains the alternate-base value loaded
inside the preceding translated `func_8005DB44`; `$a2/$a3` retain caller
entry values. The callee reads only `$a0`. The preceding retail operation is
the selected jump-table dispatch; the following operation is the epilogue
jump whose delay consumes `$v0`.

`sltiu s1,v0,1` implements exactly `s1 = (uint32_t)v0 < 1`: provider return
zero becomes `func_80053D2C` return 1; `1`, `0xFFFFFFFF`, representative
positive non-one `7`, and high guest pointer `0x800C0EAC` all become 0. The
value is normalized only in the caller and is not signed. It is neither
inverted again nor preserved. `func_80053D2C` returns `s1` at `0x80053E4C`.

On the real-disc entry path the first call is `func_8005CCA4` site
`0x8005CDC8`, whose delay sets argument `0x44`; the returned status is
discarded because `0x8005CDD0` immediately calls `func_80053D2C(0x96)`.
No `func_80053D2C` persistent write precedes the type-1..9 dependency. All
record copy and shared-state commits are therefore B41 effects; no additional
caller write follows it. Repeated calls re-scan current state. A successful
call makes the copied record occupied and writes its mapping, so identical
state naturally chooses the next free record and ID slots; a failed call
leaves state unchanged and retries identically.

## Exact footprints, determinism, and repeat behavior

- Record-scan reads are one byte each at
  `0x800C0EAC + 0x20*i`, `i=0..127`, stopping at the first zero. Their fixed
  minimum is `0x800C0EAC`; maximum is `0x800C1E8C`.
- ID-scan reads are signed little-endian halfwords at
  `old_D_8009D048 + 2*i`, stopping at the first zero or the exact unsigned
  wrapped end. For any valid checked guest state, the start may range from
  `0x80000000` through `0x801FFFFE`.
- Success reads exactly 32 logical source bytes from the dependency result,
  in the two 16-byte groups shown above. Across valid guest states those
  bytes can extend from `0x80000000` through `0x801FFFFF`. The dependency's
  fixed reads span `0x800A8034..0x800A803B`; `func_80052F70` reads
  `0x800C0E0C`.
- The exact direct guest writes on success are 32 bytes at the selected
  destination (`0x800C0EAC..0x800C1EAB` across all slots) and one halfword at
  `0x800C0E48 + 2*id_slot`, after the primary-base commit. For a malformed
  but checked state the latter can begin anywhere `0x80000000..0x801FFFFE`;
  it is never clamped. Failure paths perform no persistent write.
- The record range is guarded by its exclusive end. The copy has exact
  adjacent-byte guards in production tests, and the mapping write is exactly
  16 bits. A full 2 MiB snapshot proves no other direct guest byte changes.

The function has no executable/rodata data read, hardware access, polling,
wait, or blocking. It is deterministic from guest RAM plus the four
authoritative fields and translated `D_8009D018`; it is not dependent on host
time or environment. Address zero remains invalid: a zero archive source is
not replaced, mirrored, or fabricated, and checked memory access stops it.
