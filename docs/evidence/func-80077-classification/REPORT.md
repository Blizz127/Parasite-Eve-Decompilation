# 0x68378–0x68438 zero-span classification audit

Status: **not matching-C progress; no batch commit**.

## Result

All seven spans are **C — alignment/padding between neighboring functions**.
They are not callable functions and must remain `asm` spans. The rejected
file-scope-assembly `.c` candidates were untracked diagnostics and have been
removed; they never belonged in the matching-C count.

The committed baseline already recorded every start as `[address, asm]` and
the neighboring real functions as C. The generated `func_` names in the
individual `.s` files are split/disassembler labels at the segment start;
they are not evidence of a callable retail function.

## Reference and control-flow audit

- Direct callers / branch or jump targets to each of the seven exact VAs:
  **none** in a full retail `objdump -D` scan.
- Raw little-endian literals for each exact VA in `SLUS_006.62`: **none**.
- Relocations targeting any exact start: **none**; the original spans are
  raw split asm, not linked callable C objects.
- The preceding real function returns in its own `jr` delay slot, so control
  does not fall through from it into the zero span.
- The zero span has no terminator. If entered by an invalid/arbitrary jump,
  the three nops physically fall through into the following real function;
  there is no intentional edge proving entry.
- The generated `nonmatching func_...` label covers only the first zero word
  (`endlabel` follows it); the other two words are plainly trailing fill.

Therefore `RETAIL_CLASSIFICATION=alignment/padding`, not a real callable
three-nop function, dead function storage, reserved table, or patch space.
