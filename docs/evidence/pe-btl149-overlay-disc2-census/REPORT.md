## Overlay-range coverage

The retail executable's `D_8009315E..D_8009317A` image-load tables provide the
following increasing PE.IMG LBA ranges:

```text
[039F,03C5) [03C5,03C9) [03C9,03D2) [03D2,0457)
[0457,04FC) [04FC,0516) [0516,060B) [060B,0700)
[0700,07B7) [07B7,07E0) [07E0,0839) [0839,089D) [089D,08B0)
```

The scanner checks every range for:

- raw packed token `0xA8066048`;
- `lui 0xA806` followed by same-register `ori/addiu 0x6048`;
- direct `D_8009D280` memory writers, accounting for MIPS `%hi` carry.

It also performs the raw-token, token-construction, and direct-writer scans
over the complete 206 MB PE.IMG, not only those ranges.

## Result: a real overlay destination chooser exists

The only PE.IMG range with direct destination-state writers is
`[0x0700,0x07B7)`, byte range `[0x380000,0x3DB800)`, PE.IMG SHA-1
`9f8786a9d6f8b11548a14680d34fc540d8e909de`.

At raw offsets `0x383040..0x383358` it is executable MIPS code. The chooser
reads state and selects computed scene tokens from conditions including:

- `D_800A7918 == 0x80`, `0x78`, `0x208`, `0x210`, `0x1C0`, `0xD0`, `0x178`,
  `0xE0`, `0xB8`, and `0x148`;
- `D_800A77FC` bit `0x2000`;
- an indirect index from `D_801ACA68`, dispatched through `D_8019F034`.

The three direct stores to the field-loader destination state are:

| PE.IMG offset | Retail instruction | Value path |
|---:|---|---|
| `0x383060` | `sw a0,0xD280(at)` after `lui at,0x800A` | initializes `0xA9400048` |
| `0x383230` | `sw v0,0xD280(at)` after `lui at,0x800A` | computed `0xA8003448` branch |
| `0x383258` | `sw v0,0xD280(at)` after `lui at,0x800A` | computed `0xA8029148`/`0xA80290C8` branch |

The `lui 0x800A` detail is material: with signed offset `0xD280`, it forms
`0x8009D280`, not `0x800AD280`. Thus this is a newly proven runtime-loaded
writer family, not a different global.

The chooser also materializes nearby hardcoded tokens such as
`0xA80650C8`, `0xA80630C8`, and `0xA8067248`, plus several `0xA800`/`0xA802`/
`0xA804` tokens. It does **not** materialize `0xA8066048`.

```text

PE.IMG raw 0xA8066048 occurrences                      = 0
PE.IMG A806->same-reg 6048 constructions               = 0
PE.IMG direct D_8009D280 writers outside [0700,07B7)   = 0
```

The three zero-backed executable stubs previously identified remain zero in
both identical executables:

```text
func_801235DC @ EXE file 0x113DDC
func_801909B4 @ EXE file 0x1811B4
func_8019234C @ EXE file 0x182B4C
```

The PE.IMG census proves that the archive contains a destination chooser and
the missing writer class, but it does not prove that the chooser's indirect
`D_8019F034` branch can return m0360i. That table/entry mapping and the
external event precondition remain the unresolved dynamic boundary.

## Consequence for BTL148

BTL148's statement “no such writer in the inspected Disc 1 executable” is
still correct for the main executable, but it was incomplete about runtime
loaded PE.IMG code. The corrected provenance boundary is:

```text
runtime-loaded PE.IMG chooser
  -> state inputs (D_800A7918, D_800A77FC, D_801ACA68)
  -> computed destination candidates
  -> D_8009D280
  -> field/package loader
```

The static census does not yet establish:

```text
retail event precondition -> chooser input state -> m0360i
```
