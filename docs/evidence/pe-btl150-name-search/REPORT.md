# PE-BTL150 — name-form search for m0360i

Date: 2026-08-24

## Result

The token identity is confirmed, not assumed:

```text
0xA8066048 -> m0360i
pack("m0360i") -> 0xA8066048
```

The static name/index search found no m0360i name spelling and no packed
m0360i token in either retail executable or either complete 206 MB PE.IMG.
The package table does contain the known table position 359, but its entry is
numeric package metadata and does not carry a name or an independently
resolvable m0360i association.

## Retail packing proof

`func_8006E2D0` decodes six fields from the input token using shifts
`27, 22, 17, 12, 7, 2`, masks each field with `0x1F`, and indexes
`D_800930B4`. The retail alphabet bytes at `D_800930B4` are:

```text
0123456789abcdefghiklmnopqrstuvwxy
```

The alphabet intentionally omits `j`. `func_8006E3D4` is the inverse packer
called by the two known executable name-packing handlers `func_80015790` and
`func_80015964`; it maps each six-character input back to the same six 5-bit fields. The
round-trip values are:

| name | packed token |
|---|---:|
| `m0005i` | `0xA80002C8` |
| `m0295i` | `0xA80492C8` |
| `m0291i` | `0xA80490C8` |
| `m0424i` | `0xA8082248` |
| `m0367i` | `0xA80663C8` |
| `m0360i` | `0xA8066048` |

For `0xA8066048`, the six extracted indices are `[21, 0, 3, 6, 0, 18]`,
which select `m`, `0`, `3`, `6`, `0`, `i`.

## Name-form coverage

The scanner searched both byte orders for the packed token and searched raw
ASCII lower- and uppercase spellings. It covered:

- Disc 1 and Disc 2 `SLUS` executables;
- every byte of Disc 1 and Disc 2 `PE.IMG`;
- the complete packed-token form and ASCII name form;
- the known package-table index form, including 16- and 32-bit byte orders.

Disc 2 is byte-identical to Disc 1 for both the executable and PE.IMG, so its
results are duplicate coverage rather than a distinct source.

The reproducible output is [scan.json](scan.json), generated by
`tools/research/pe_btl150_name_search.py`.

The relevant results for each distinct image are:

```text
ASCII m0360i / M0360I                  = 0
packed 0xA8066048, little-endian      = 0
packed 0xA8066048, big-endian         = 0
```

The package table base is `D_80093378`; the established m0360i package index
is 359. The executable table slot is:

```text
D_80093378 + 359 * 8 = 0x80093EB0
entry bytes             = 24 83 00 00 21 31 70 03
```

This proves the numeric slot exists in the generic indexed table. It does not
prove the slot's semantic name from static bytes: the table contains packed
package metadata, while the name is supplied to `func_8006B4F8` through the
decoded destination token. The unresolved `D_801ACA68 -> D_8019F034` runtime
dispatch therefore still has no static m0360i name/token witness.

## Consequence

BTL150 closes the token-form question. The universal zero was not caused by a
wrong token identity: `0xA8066048` is exactly `m0360i`. It also closes the
static name-form search over the available Disc 1/Disc 2 executable and
PE.IMG artifacts.

No native scheduler implementation or m0360i special case was added.
